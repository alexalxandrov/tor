# BridgePipe — Tor SOCKS5-туннель с менеджером мостов

Android-приложение (Kotlin), рассчитанное на работу в медленных сетях (2G):
поднимает локальный **SOCKS5-прокси** (по умолчанию `127.0.0.1:9050`, порт
настраивается, как у tor), само скачивает, проверяет и ротирует **мосты Tor**
(obfs4 / webtunnel / snowflake / meek / vanilla), ведёт **подробный лог по
умолчанию** и умеет **подменять SNI** в собственных HTTPS-запросах.

## Возможности

- **SOCKS5-туннель**: нативный `tor` (из официального tor-expert-bundle)
  запускается как процесс; порт и привязка настраиваются (9050 и т.п.).
- **Менеджер мостов** (список до 2000+ строк, дедупликация):
  - встроенный список Tor Browser (кладётся в APK на этапе CI);
  - свои зеркала/URL (поддержка `|sni=домен` per-источник);
  - BridgesDB (прямо или через уже поднятый туннель);
  - ручной импорт (вставка до 2000 строк);
  - скачивание списков **через тор** (чистый канал) или напрямую,
    с gzip-сжатием и жёсткими таймаутами.
- **Проверка мостов**: дешёвый TCP-connect-пинг параллельным пулом
  (почти нулевой трафик — важно на 2G), живые сортируются по latency;
  top-N уходит в конфиг tor, failover между ними делает сам tor;
  watchdog переприменяет лучшие мосты, если bootstrap завис.
- **Режим 2G**: `ReducedConnectionPadding` + `ReducedCircuitPadding`,
  повышенные таймауты, snowflake по умолчанию выключен, никакого лишнего
  трафика и картинок.
- **Verbose-лог по умолчанию**: stdout tor, события ControlPort
  (bootstrap, BW), результаты каждого пинга моста, ошибки источников.
- **SNI-подделка** (опционально): для HTTPS-запросов приложения к
  источникам мостов (когда SNI-фильтрация режет bridges.torproject.org).
  При включении проверка сертификата отключается — осознанный режим.
- **torrc-override**: произвольные строки дописываются в конфиг —
  полная совместимость с любыми опциями tor.

## Сборка на GitHub (без установки чего-либо локально)

1. Загрузите файлы проекта в репозиторий GitHub (или создайте новый
   через «uploading an existing file» / `git push`).
2. Откройте вкладку **Actions** → workflow **build-apk** запустится сам
   (или запустите вручную: *Run workflow*).
3. CI скачает официальные tor-expert-bundles (aarch64 + armv7 + x86_64),
   проверит sha256, разложит бинарники в `jniLibs`, скопирует geoip и
   строки мостов в assets, соберёт **release APK**.
4. Готовый подписанный `bridgepipe-signed.apk` — в артефактах запуска (`bridgepipe-apk`).
   (**build-apk → run → Artifacts**).

Нативные бинарники (`libtor.so`, `liblyrebird.so`, `libsnowflake.so`)
в репозиторий **не коммичатся** — они скачиваются при каждой сборке,
поэтому APK всегда собирается со свежим tor.

### Обновление версии tor

Поменяйте `TOR_BROWSER_VERSION` в `.github/workflows/build.yml` на
актуальную из https://dist.torproject.org/torbrowser/ и запушьте.

### Подпись APK

Android не устанавливает неподписанные APK. Workflow теперь всегда подписывает сборку и публикует в артефакте `bridgepipe-apk` файл `bridgepipe-signed.apk`.

Для тестового запуска без секретов CI создаёт временный ключ подписи. Такой APK можно установить, но сертификат будет уникальным для каждого запуска: чтобы поставить новую тестовую сборку поверх старой, нужно либо сначала удалить старую (это удалит её данные), либо настроить постоянный ключ подписи через секреты репозитория `KEYSTORE_B64`, `KEYSTORE_PASSWORD`, `KEY_ALIAS` и `KEY_PASSWORD`. Для долговременного использования рекомендуется постоянный ключ.


## Использование

1. «Статус» → **Запустить туннель** (фореграунд-сервис + уведомление).
2. «Статус» → **Обновить мосты из источников**, затем **Проверить мосты**.
3. Если bootstrap застрял — **Применить лучшие мосты** (рестарт tor с
   новым top-N) или подождите watchdog (90 с без прогресса).
4. Настройте браузер/приложение на SOCKS5 `127.0.0.1:9050`.
5. Всё, что происходит, видно во вкладке «Лог» — там же сгенерированный
   torrc при каждом старте.

### Холодный старт, если всё заблокировано

Если `bridges.torproject.org` недоступен без туннеля — не страшно:
в APK зашит список мостов Tor Browser (обновляется при сборке CI),
плюс добавьте свои зеркала в настройках (например, raw-файлы публичных
коллекций мостов на GitHub) или импортируйте строки вручную. Как только
туннель поднимется, дальнейшие обновления пойдут через него.

## Ограничения (честно)

- Полный «пинг» всех 2000 мостов — это TCP-фильтр; глубокая проверка
  PT-хендшейка делается для топа, остальное дорезолвливает сам tor.
- BridgesDB выдаёт понемногу и банит активных парсеров — тысячи строк
  приносят встроенный список, зеркала и импорт.
- Snowflake на 2G нестабилен (WebRTC, много соединений) — по умолчанию
  выключен.
- SNI-подделка работает только там, где сервер принимает чужой SNI
  (fronting/ECH); иначе TLS не сойдётся.
- Режим VpnService (перехват всего трафика, как Orbot) не реализован —
  только SOCKS5.

## Структура

```
app/src/main/java/com/bridgepipe/
  App.kt                      — Application
  data/     Prefs, BridgeDb    — настройки, SQLite мостов
  bridges/  Parser, Sources, Tester, Manager
  net/      Net               — HTTP(S)+gzip, SOCKS-через-tor, SNI
  tor/      TorService, ControlConnection, TorConfigBuilder
  ui/       MainActivity, адаптеры
app/src/main/assets/builtin_bridges.conf — fallback-список мостов
.github/workflows/build.yml   — CI: expert-bundle → jniLibs → APK
```

Требования: JDK 17, Gradle 8.9 (ставится CI), Android SDK 34.
